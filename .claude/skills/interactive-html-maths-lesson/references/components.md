# Component Library

The template implements nine reusable components. Each has a CSS class signature, an HTML pattern, and a JavaScript hook (where applicable). When adapting the template for a new topic, use these components as-is and just swap the content. If a lesson needs a component the template doesn't have, build new — but follow the same code style.

## 1. Vocabulary flip card

5 cards in a grid, each flipping to show definition + example footer.

**When to use**: vocabulary section (Section 2) where students need to learn 3–7 key terms before working with them.

**Order**: concrete → abstract → composite. E.g. for "Collecting Like Terms": Constant → Variable → Coefficient → Term → Like terms.

**Pattern**:

```html
<div class="vocab" onclick="this.classList.toggle('flipped')">
  <div class="vocab-inner">
    <div class="vocab-front">{TERM}<div class="hint-flip">Tap to flip</div></div>
    <div class="vocab-back">
      {Definition. Use <strong> for the key phrase — coral coloured automatically.}
      <div class="vocab-example expr">{Example: "In 4x − 7: the constant is <strong>−7</strong>."}</div>
    </div>
  </div>
</div>
```

**Notes**:
- Definition stays plain text. Coral bold via `<strong>`.
- Example footer is in a light-blue tinted box with an uppercase "EXAMPLE —" label generated by CSS.
- Card height is 200px to accommodate longer content. Don't shrink without testing all five.
- Grid is `repeat(auto-fit, minmax(175px, 1fr))` — fits 5 columns on desktop, collapses gracefully on mobile.
- `text-wrap: balance` is applied to both definition and example so lines distribute evenly.

## 2. Drag-and-drop sort

A strip of draggable chips, two (or more) buckets to drop them into. Used for sorting/classifying items.

**When to use**: classification tasks — e.g. "is this a variable term or a constant term?", "is this an integer or rational?", "Pythagorean triple or not?".

**Pattern**:

```html
<div class="parts-expr">
  <div class="label">{Optional context line above the chips}</div>
  <div id="partsTerms" class="terms-source">
    <span class="term-chip expr" data-type="{correct-bucket}">{chip content}</span>
    <!-- ... more chips ... -->
  </div>
  <div class="parts-buckets">
    <div class="bucket" data-bucket="{type-1}">
      <h4 class="vt">{Bucket 1 label}</h4>
      <div class="bucket-contents expr"></div>
    </div>
    <div class="bucket" data-bucket="{type-2}">
      <h4 class="ct">{Bucket 2 label}</h4>
      <div class="bucket-contents expr"></div>
    </div>
  </div>
  <div class="parts-actions">
    <button class="btn-secondary btn-sm" onclick="resetSort()">↺ Reset</button>
    <button class="btn-secondary btn-sm" onclick="solveSort()">Show solution</button>
  </div>
</div>
```

**JavaScript** (already in template — don't reimplement): `initDragSort()` sets up Pointer Events on every `.term-chip[data-type]`. Wrong drops shake and return to source automatically.

**Notes**:
- Use Pointer Events not legacy mouse/touch — works on smartboard pen, mouse, and touch.
- The `data-type` attribute on chips and `data-bucket` on buckets must match for a drop to count as correct.
- For more than 2 buckets, add additional `.bucket[data-bucket="..."]` elements; the JS auto-handles any number.

## 3. Click-to-match pairs

A grid of items where students click two at a time to pair them up. Pairs highlight in different colours.

**When to use**: identifying relationships — like terms, equivalent fractions, function-graph pairs, formula-name pairs.

**Pattern**:

```html
<div class="match-area" id="matchArea">
  <!-- populated by JS from matchTerms array -->
</div>
<div class="match-feedback" id="matchFeedback">Pick a term to start matching.</div>
```

**JavaScript data**:

```js
const matchTerms = [
  { html: '3<span class="var">x</span>', group: 1 },
  { html: '11<span class="var">x</span>', group: 1 },
  // ... groups 2, 3, 4, 5
];
```

Each pair shares a `group` number. The template handles shuffling, click-pair detection, colour assignment per group, and feedback messages.

**Notes**:
- Up to 5 colour-coded groups supported in the CSS (`.matched-1` through `.matched-5`). Add more `.matched-N` classes if you need more pairs.
- Wrong matches flash both chips then deselect — no penalty.

## 4. Worked example with step reveal

Used in I Do (Section 5). Three numbered steps that fade in on button click.

**When to use**: I Do section, always. The 3-step structure (identify → apply → verify) mirrors the user's PowerPoint house style.

**Pattern**:

```html
<div class="worked">
  <div class="step visible" id="step1">
    <div class="step-num">1</div>
    <div class="step-body">
      <div class="step-title">Identify like terms</div>
      <div class="step-desc">{What this step does, in one sentence}</div>
      <div class="calc-box">{The maths — use .red and .blue spans for emphasis}</div>
    </div>
  </div>

  <div class="step" id="step2">
    <div class="step-num">2</div>
    <div class="step-body">
      <div class="step-title">{Apply the operation}</div>
      <div class="step-desc">{...}</div>
      <div class="calc-box">{...}</div>
    </div>
  </div>

  <div class="step" id="step3">
    <div class="step-num">3</div>
    <div class="step-body">
      <div class="step-title">{Verify / interpret}</div>
      <div class="step-desc">{...}</div>
      <div class="calc-box">{...}</div>
      <div class="summary-banner">
        <span class="label">Answer</span>
        {Final answer}
      </div>
    </div>
  </div>

  <button class="reveal-btn" id="revealBtn" onclick="revealNextStep()">Reveal next step ↓</button>
</div>
```

**Notes**:
- Step 1 has `.visible` class by default; others fade in via `revealNextStep()`.
- Use `.red` for variable terms, `.blue` for constants (or whichever colour scheme is natural for the topic).
- The `.summary-banner` is coral with white text and goes at the end of step 3 — the boxed final answer.
- Verification should be substitution where possible (substitute a value, check both forms give the same result).

## 5. Practice problem

Single problem with input field, Check button, hint toggle, show-answer toggle. Auto-marks and updates progress bar.

**When to use**: Practice sections (Quick check, Building, Stretch, Mastery, Exit ticket).

**Pattern** (problems are JS-generated, not hand-written HTML):

```js
const practice1 = [
  { q: '4<span class="var">x</span> + 7<span class="var">x</span>', a: '11x', hint: 'Both terms have x. Add the coefficients: 4 + 7.' },
  { q: '<span class="var">k</span> − 6<span class="var">k</span>', a: '-5k', hint: 'k means 1k. So 1 − 6 = −5.' },
  // ...
];

buildPractice('practiceGrid1', practice1, 'P');
```

The `buildPractice` function renders each problem as a card with input, Check button, hint, and answer toggles.

**Answer normalisation**:
- Strip spaces and lowercase before comparing.
- Accept reordered terms: `3x+5` is equivalent to `5+3x` (sorted-terms comparison).
- Accept reordered factors: `(x+4)(x+5)` is equivalent to `(x+5)(x+4)`. Also handles term-reordering within each factor, optional leading coefficients like `2(x+1)(x+3)`, and negative factors. Two-bracket products only; three-or-more-bracket products are not auto-accepted in either order.
- Strip leading `+`.

**Special answer values**:
- `a: 'TEXT'` — open-response question; no Check button, hint and Show answer still work; doesn't count toward progress.

**Options**:
- `buildPractice(containerId, data, prefix, { noCount: true })` for We Do — answers don't affect the student's overall score since the work is co-produced.

**Prefix conventions** (used as the problem number, e.g. "P1" / "M3" / "C2"):
- P = Practice (single variable)
- M = Multi-variable practice
- C = Challenge / fractions
- Q = Quick check
- W = We Do
- E = Exit ticket

## 6. Checkpoint / Stop banner

Used in Section 7 (Quick check) to mark the pause point between teacher-supported and independent work.

**Pattern**:

```html
<section class="lesson checkpoint">
  <h2>
    <span class="sec-num">7</span>Quick check — try these on your own
    <span class="checkpoint-tag">✋ Stop &amp; check</span>
  </h2>
  <p class="sec-desc">{What students do here, plus the "stop after these" instruction}</p>
  <div class="practice-grid" id="checkpointGrid"></div>
  <div class="stop-banner">
    ✋ <strong>Stop here</strong> when you're done. Don't start the chilli practice yet — wait for the class check.
  </div>
</section>
```

**Notes**:
- Light blue background, navy left accent — distinguishes from both regular sections (white) and chilli tiers (mint/wheat/terracotta).
- The "✋ Stop & check" tag is a navy pill.
- Two questions is typical (single variable, achievable, tests core understanding).

## 7. Teacher mode toggle

Top-right button that toggles `body.teacher-mode`. Reveals all answers, all hints, and all worked-example steps at once. Used by the teacher for end-of-class review or board projection.

**Pattern**: already in the template — don't rebuild. The toggle lives in the sticky progress bar.

**CSS targets** (already wired):
- `body.teacher-mode .answer-box { display: block !important; }`
- `body.teacher-mode .hint-box { display: block !important; }`
- `body.teacher-mode .step { opacity: 1 !important; }`
- `body.teacher-mode #revealBtn { display: none; }`

## 8. Phase banner

Horizontal banner between sections marking transitions between gradual-release phases.

**Pattern**:

```html
<div class="phase-banner">
  <div class="phase-mono">I DO</div>
  <div class="phase-text">
    <div class="phase-label">Watch and listen</div>
    <div class="phase-sub">I'll work through one example out loud, showing every step.</div>
  </div>
</div>
```

**Used at**:
- Before Section 2: "AS A CLASS"
- Before Section 5: "I DO"
- Before Section 6: "WE DO"
- Before Section 7: "YOU DO"

**Notes**:
- Warm-up (Section 1) and Exit ticket (last section) don't get banners — they're book-ends.
- The `phase-mono` text uses Georgia bold with letter-spacing, coral colour.
- Subtitle is italic muted text.

## 9. Draggable-vertex constant-area triangle

An interactive triangle whose apex slides along a fixed-height guide line. The base
and the perpendicular height are held constant, so the area never changes — a visual
proof that a triangle's area depends only on base and perpendicular height, not on its
shape. As the apex moves past either base endpoint the triangle becomes obtuse and the
perpendicular foot falls outside the base, so students meet all three triangle types.

**When to use**: the AS A CLASS phase (Section 3 or 4) of an area-of-triangles lesson,
or any lesson where students need to *see* an invariant hold under a transformation.
This component is the in-house substitute for "dynamic geometry software" — it satisfies
AC9M7M01 elaboration 2 ("…sliding of the vertex of a triangle at a fixed altitude
opposite a side leaves the area of the triangle unchanged") as a self-contained
interactive: no external DGS, no internet, one file.

**Pattern** (HTML): a section card holding a two-column `.cat` layout — an SVG stage on
the left, a readout panel on the right. The SVG carries a fixed base line, a dashed
fixed-height guide line, the triangle fill and slanted sides, a perpendicular drop with
a right-angle marker, and the draggable apex handle. The readout panel shows base,
height, live triangle type, and the live area expression. See
`assets/components/constant_area_triangle.html` for the full markup — adapt the numeric
labels to the lesson's chosen base/height.

**JavaScript**: `initConstantAreaTriangle(config)` — NEW and additive. It does not touch
any of the eight locked template functions (`buildPractice`, `checkAnswer`,
`answerMatches`, `formatAnswerDisplay`, `updateProgress`, `toggleHint`, `toggleAnswer`,
`toggleTier`). All component state is scoped inside the init call, so the component can
be instantiated more than once on a page by passing distinct element IDs.

`config` fields:

| Field | Meaning |
|---|---|
| `svgId` | id of the component's `<svg>` |
| `ids` | object mapping the component's internal element ids (apex, fill, slants, perp, etc.) |
| `Ax`, `Bx`, `baseY`, `guideY` | SVG coordinates of the base endpoints and the two horizontal lines |
| `minX`, `maxX` | apex travel range — set wider than `Ax`/`Bx` so the obtuse case is reachable |
| `startX` | apex starting x (use the midpoint for an isosceles start) |
| `baseCm`, `heightCm` | real-world values shown in the readout; area is computed as ½·base·height |

**Notes**:
- Pointer Events — works on smartboard pen, touch, and mouse. `touch-action: none` on
  the SVG and the handle stops the page scrolling or zooming mid-drag.
- The apex travel range deliberately extends past both base endpoints so students reach
  the obtuse case — the perpendicular foot landing outside the base is the case AC9M7M01
  and the area-of-triangles lesson both call out explicitly.
- Triangle type (right-angled / acute / obtuse) is computed live from the foot position
  and shown in the readout.
- The area value is **computed** (`½ × baseCm × heightCm`), never hardcoded — the whole
  point is that the recomputed number does not move as the apex slides.
- Keyboard accessible: the apex handle is focusable (`role="slider"`), arrow keys nudge
  it, Shift+arrow takes a larger step. A focus ring appears on keyboard focus.
- An exploration nudge in the readout confirms, once the student has produced all three
  triangle types, that the area stayed constant throughout.
- House style: navy base and slanted sides, coral guide line / perpendicular / apex
  handle, light-coral triangle fill — all from the standard palette variables.

**Pairs with the curriculum panel**: when a lesson includes this component, the
"Elaborations covered" panel row can legitimately list the DGS-style elaboration
(e.g. AC9M7M01 E2), because the component delivers that elaboration's mathematical
intent. Without the component, that elaboration should not be claimed.

## DGS-substitute interactive components — the pattern

Component 9 (draggable-vertex constant-area triangle) is the first of a *family*:
self-contained SVG+JavaScript interactives that stand in for "dynamic geometry
software" (DGS). Many AC9 elaborations name DGS explicitly as the method — for example
AC9M7M01 E2, AC9M7M02 E4, AC9M7M04 E1/E2/E3. The lessons cannot use Desmos or GeoGebra
without breaking the single-file, offline, no-dependency rule. Instead, build a
purpose-made interactive that delivers the elaboration's *mathematical intent*.

**When to build a new one**: a lesson maps to an elaboration whose text says "using
dynamic geometry software to…" (or "spatial reasoning and prediction to…", or
"constructing … using a pair of compasses and a ruler"). If an existing component in
this file already covers that interaction, adapt it. If not, build a new one following
the rules below, and add it to this file as the next numbered component.

**Rules every DGS-substitute component follows** — so the family stays consistent:

1. **Self-contained.** Pure SVG + vanilla JavaScript. No libraries, no CDN, no web
   fonts, no internet at runtime. The lesson must still open offline on the school
   network.
2. **Additive JavaScript.** Each component exposes a single `init<Name>(config)`
   function. It must not modify or depend on the eight locked template functions
   (`buildPractice`, `checkAnswer`, `answerMatches`, `formatAnswerDisplay`,
   `updateProgress`, `toggleHint`, `toggleAnswer`, `toggleTier`). All state lives inside
   the init call so multiple instances can coexist.
3. **Config-driven.** No values hardcoded in the function body. The lesson's numbers
   (lengths, angles, starting positions, real-world units) are passed in `config`, so
   the same component serves many lessons.
4. **Pointer Events, not mouse/touch.** Handles use `pointerdown`/`pointermove`/
   `pointerup` so smartboard pen, finger, and mouse all work. Set `touch-action: none`
   on the SVG and on every draggable handle.
5. **Manipulate, observe, generalise.** The interaction must let the student *change*
   something and *see* a mathematical consequence — ideally an invariant holding, or a
   relationship updating live in a readout. A static diagram is not a DGS substitute.
6. **Show the obtuse / edge / degenerate case.** DGS earns its place by letting students
   reach cases a textbook figure hides. Make drag ranges wide enough to reach them.
7. **Keyboard accessible.** Handles are focusable with `role="slider"`; arrow keys nudge;
   a focus ring appears on keyboard focus.
8. **Live values are computed, not hardcoded.** If the component shows a quantity
   (area, angle, volume), recompute it from the current state every redraw — the
   teaching point usually depends on the recomputed value behaving a certain way.
9. **House style.** Navy `#1D2B5E` for primary geometry, coral `#E8485A` for the
   interactive/handle elements and anything being measured, light-coral fill for
   regions, all via the palette variables. The component sits in a standard section
   card and is placed in the AS A CLASS phase unless the lesson says otherwise.

**Documenting a new one**: add it as the next numbered component in this file, with the
same sub-headings used throughout — a one-paragraph description, **When to use** (name
the AC9 elaboration it satisfies), **Pattern**, **JavaScript**, **Notes**. Then update
the component count in this file's intro line and add a bullet to the Component library
list in `SKILL.md`. Note in the entry which elaboration it lets the curriculum panel
legitimately claim.

## Difficulty section wrapper

Apply to YOU DO practice sections (Sections 8, 9, 10) to enable the chilli sticker and tinted background.

**Pattern**:

```html
<section class="lesson difficulty-1">
  <h2>
    <span class="sec-num">8</span>Practice — single variable
    <span class="diff-badge d1"><span class="dots">●○○</span>Building</span>
  </h2>
  <p class="sec-desc">{...}</p>
  <div class="practice-grid" id="practiceGrid1"></div>
</section>
```

Classes: `difficulty-1` (Building), `difficulty-2` (Stretch), `difficulty-3` (Mastery).

The chilli stickers (🌶 / 🌶🌶 / 🌶🌶🌶) are added via CSS `::before` automatically — no need to write the emojis in HTML. Same for the bold pill badges (just match `.diff-badge d1` / `d2` / `d3`).
