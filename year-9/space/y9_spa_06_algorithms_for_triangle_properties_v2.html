1Why this matters

A real situation that is secretly today's maths.

A landscaping company sells triangular garden-bed kits online. Customers type in three edge lengths and the website quotes $45 per metre of steel edging.

One customer typed 1 m, 2 m and 5 m. The website happily charged them $360, but those pieces can never join up into a triangle. That is a refund, a wasted delivery and an angry review.

A computer cannot look at three sticks. It needs an algorithm: exact steps and yes/no decisions. Today you design one that tests any three lengths using the triangle inequality, then a second one that builders use to generate right-angled triangles with whole-number sides.

5Worked example — the 3-step method

Design an algorithm that decides whether three lengths can form a triangle, then test it on three inputs: 4, 6, 9 and 3, 8, 4 and 2, 5, 3.

1
Design the steps and the decision
Find the longest length first; only one comparison is then needed. The diamond is the decision.
2
Write it as pseudocode
Same algorithm, written in lines. Every flow-chart shape becomes one line.
1 INPUT three lengths
2 SET c = the longest length; a, b = the other two
3 IF a + b > c THEN
4   OUTPUT “Triangle”
5 ELSE
6   OUTPUT “Not a triangle”
3
Test with three cases
Good testing uses a clear yes, a clear no and an edge case that sits exactly on the boundary.
4, 6, 9 → c = 9, 4 + 6 = 10 > 9 → Triangle
3, 8, 4 → c = 8, 3 + 4 = 7, not > 8 → Not a triangle
2, 5, 3 → c = 5, 2 + 3 = 5, not > 5 → Not a triangle (flat)
Answer The algorithm sorts first, then makes one decision: is the sum of the two shorter sides greater than the longest?

★Test and refine: spot the bug

Riley wrote a shorter triangle algorithm with no sorting step: “IF a + b > c THEN OUTPUT Triangle”. Riley tested it on the lengths 3, 10, 4. Click the line where the algorithm first goes wrong.

Lengths entered in this order: 3, 10, 4. Can they form a triangle?
1 Input the lengths: a = 3, b = 10, c = 4.
2 The algorithm compares a + b with c.
3 3 + 10 = 13, and 13 > 4.
4 Output “Triangle”.

✓ Right: that's the bug.

Why: Riley's algorithm treats whatever was typed third as the longest side. Here c = 4 is not the longest; 10 is. The two shorter sides are 3 and 4, and 3 + 4 = 7 is not greater than 10, so the correct output is “Not a triangle”. Refinement: add the step “let c = the longest length” before the decision.

Now fix line 2: after the refinement, which length should be compared with the sum of the other two?
