1Why this matters

A real situation that is secretly today's maths.

A sign shop owns a laser engraver. It cannot use a protractor. It only knows two moves: draw an arc (like a compass) and draw a straight line through two points (like a ruler with no markings).

The shop is charged $2.50 for every instruction the engraver runs. A vague instruction such as “draw a line about halfway” wastes an acrylic sheet. A missing step wastes money too.

To cut an exact angle, the shop needs an algorithm: precise steps, in order, with decisions where needed. Today you design compass-and-straightedge algorithms that bisect an angle and construct 60°, 30° and 15°, then test and refine them so they work every time and cost less.

5Worked example — the 3-step method

Design an algorithm that bisects any angle ∠AOB using only a compass and a straightedge, then test it on three angles: 80°, 150° and 30°.

1
Design the steps
Every step names the compass centre, the width and what to mark. The arcs from A and B use the same width, so P is the same distance from A as from B.
2
Write it as pseudocode, with a decision
If the width is too small, the arcs from A and B miss each other. The algorithm needs a decision to handle that.
1 PLACE compass on O; DRAW an arc crossing both arms
2 MARK A and B where the arc crosses the arms
3 SET width w greater than half of AB
4 DRAW an arc centre A, width w, inside the angle
5 DRAW an arc centre B, same width w
6 IF the arcs do not cross THEN increase w; GO TO 4
7 MARK P where the arcs cross
8 DRAW the ray OP; OUTPUT “OP bisects ∠AOB”
3
Test with three cases
Run the algorithm on an ordinary angle, a large (obtuse) angle and a small angle, then measure both halves.
80° → ∠AOP = 40°, ∠POB = 40° ✓
150° → ∠AOP = 75°, ∠POB = 75° ✓
30° → ∠AOP = 15°, ∠POB = 15° ✓
Why it works OA = OB (same arc) and AP = BP (same width), and OP is shared. So triangles OAP and OBP are congruent (SSS), and ∠AOP = ∠POB every time.

★Order the algorithm: a 30° angle

This algorithm combines the 60° construction with the bisector, but the steps are jumbled. Use ▲ and ▼ to put them in an order a machine could follow, then click Check order. Ask: does this step use a point that has not been marked yet?

Goal: construct ∠AOP = 30° using only a compass and a straightedge.
  • DRAW ray OB (∠AOB = 60°).
  • DRAW a ray from O; MARK A on it.
  • DRAW ray OP; OUTPUT ∠AOP = 30°.
  • PLACE compass on A, same width; MARK B where it crosses the first arc.
  • DRAW equal-width arcs centred on A and on B; MARK P where they cross.
  • PLACE compass on O, width OA; DRAW a long arc through A.

★Test and refine: spot the bug

Jordan wrote a bisector algorithm and tested it on a 70° angle. The test failed: the two angles came out as 19° and 51°. Click the line where Jordan's algorithm first goes wrong.

Test case: bisect ∠AOB = 70°. Expected output: two angles of 35°.
1 Compass on O, width 4 cm: draw an arc crossing both arms at A and B.
2 Compass on A, width 3 cm: draw an arc inside the angle.
3 Compass on B, width 5 cm: draw an arc crossing the first at P.
4 Draw the ray OP and output “OP bisects ∠AOB”.

✓ Right: that's the bug.

Why: P must be the same distance from A and from B. With widths of 3 cm and 5 cm, AP ≠ BP, so triangles OAP and OBP are not congruent and OP leans towards A. Refinement: write “keep the same width” into line 3, and test again on more than one angle.

Now fix line 3: what width, in cm, should the arc centred on B use?
